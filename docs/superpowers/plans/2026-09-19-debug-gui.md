# デバッグGUI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 既存の七聖召喚エンジンを変更せず、Tkinterから合法Actionを手動実行し、GameStateとイベントを細かく確認できるデバッグGUIを追加する。

**Architecture:** GUIは `gui/` に閉じ、Controllerが既存の `Game` / `Action` APIを呼び出す。表示用のState/ViewModelとイベントログをゲーム状態から分離し、GUIウィジェットは表示・入力だけを担当する。Phase 1はゲーム生成、状態表示、合法Action、対象選択、実行、イベントログまでを実装し、CPU詳細・状態編集・JSON保存は後続フェーズへ残す。

**Tech Stack:** Python 3.14, Tkinter, pytest。GUI専用の外部依存は追加しない。

**Spec:** `docs/superpowers/specs/2026-09-19-debug-gui-design.md`

## Global Constraints

- Tkinterベースのメインウィンドウ
- GUIから既存の合法Actionを選択・実行する
- GUI側へゲームルールや合法性判定を重複実装しない
- Player/CharacterのHP、Energy、元素、元素付着、ダイス、Phase、手番を確認できる
- 合法Action、対象、コストを確認できる
- Action/Event履歴を時系列で確認できる
- 不正操作でGUIをクラッシュさせずエラー表示する
- GUI専用の外部依存を追加しない
- `python run_gui.py` で起動できる
- 既存テストスイートを全件通過させる

## Review Focus

- Game APIの実際のAction実行入口とイベント取得方法がGUIの想定と異なる場合に、既存経路を壊さず適応すること。
- `Action` のtarget/cost表現が種類ごとに異なる場合でも、表示変換が例外を出さないこと。
- ROLLフェーズや対象付きActionでも合法Action一覧と実行経路が一致すること。
- ゲーム終了後にAction操作を行っても状態を変更せずGUIを維持すること。
- Tkinterが利用できないヘッドレス環境でも、表示変換・ControllerのテストがTk初期化を要求しないこと。
