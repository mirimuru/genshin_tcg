## ダイスシステム

現在は正式ルールへの段階的な移行を目的としたダイスシステムです。

- プレイヤーは初期状態で8個の万能ダイスを持つ
- 次ラウンド開始時に8個のダイスを再生成する
- 生成対象は元素7種（炎・水・風・雷・草・氷・岩）と万能
- 通常攻撃・元素スキル・元素爆発は3個のキャラクター元素ダイスを要求
- 万能ダイスは元素ダイスの代用として使用可能
- 通常のキャラクター交代は任意のダイス1個を消費
- 戦闘不能による強制交代は無料
- ダイス不足の行動は `get_legal_actions()` から除外
- `execute_action()` でもダイス不足を検証する
- `DicePool.roll()` はテスト時に `random.Random` を渡して再現可能なダイス生成を行える
- 不要な元素ダイス1個を、アクティブキャラクターの元素ダイス1個へ調和できる
- 調和は高速行動として扱い、調和後も同じプレイヤーの手番を維持する
- 万能ダイス・任意ダイス・同じ元素は調和対象外
- CPUは攻撃・スキルに必要な元素ダイスが不足している場合、調和を優先して選択できる

正式な七聖召喚の調和、再ロール、キャラクター元素を考慮した詳細な生成ルールなどは今後拡張します。

## 合法手生成

`Game.get_legal_actions(player_id)` は、現在のゲーム状態と手番を確認し、実行候補となる行動の一覧を返します。

現段階で考慮する条件は次のとおりです。

- ゲーム終了後は合法手なし
- 手番でないプレイヤーは合法手なし
- 全キャラクターが戦闘不能なら合法手なし
- アクティブキャラクターが戦闘不能なら、別の生存キャラクターへの強制交代のみ可能
- ダイスコストを満たす通常攻撃、元素スキル、条件を満たす元素爆発を生成
- 調和可能な不要元素ダイスがある場合、調和アクションを生成
- ダイス1個を支払える場合に生存している別キャラクターへの交代を生成
- ラウンド終了を生成

カードの使用条件、元素反応などは今後追加します。

## CPUの行動選択

CPUは合法手一覧から、次の優先順位で行動を選択します。

1. 強制交代
2. 元素爆発
3. HPが低い場合の交代
4. 元素スキル
5. 通常攻撃
6. 攻撃・スキルを可能にする調和
7. ラウンド終了

CPUには合法手だけが渡されるため、ダイス不足の攻撃などを直接選択することはありません。

これは初期段階のヒューリスティックであり、将来的には敵のHP、撃破可能性、元素反応、ダイス、カード、キャラクター相性などを評価します。

## CPU対CPU対戦ループ

2人のプレイヤーオブジェクトを渡すことで、1手または複数手の自動進行ができます。

```python
from engine.game import Game
from players.cpu import CpuPlayer

players = [CpuPlayer(), CpuPlayer()]

action = game.step(players)                 # 1手だけ進める
history = game.run(players, max_actions=1000)  # 最大1000手まで進める
```

`step()`は現在の手番の合法手を取得し、プレイヤーの`choose_action()`を呼び出して、選択された行動を実行します。`run()`はゲーム終了または`max_actions`到達まで`step()`を繰り返します。

プレイヤーが合法手に含まれない`Action`を返した場合や、合法手が存在しない場合は例外を発生させます。
